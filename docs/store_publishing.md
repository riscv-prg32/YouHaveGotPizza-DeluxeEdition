# Publishing on the PRG32 Cartridge Store

Release 1.0.0 ships one bundle:

| Bundle | Store id | Contents |
|---|---|---|
| `dist/you-have-got-pizza-deluxe-1.0.0-store.zip` | `org.riscv-prg32.you-have-got-pizza-deluxe` | `manifest.json`, `icon.png`, `splash.png`, both `.prg32` files |

It was validated with CartridgeStore's own ingestion code (`_prepare_bundle()`, the implementation of
`POST /api/publish/bundle`, at commit `734653e`) and is **ready for submission**. It has **not** been
submitted: publishing is an authenticated, human-approved step. Checksums are in `dist/SHA256SUMS`.

## Bundle format (CartridgeStore `docs/api.md`, "Bundle Publish")

```text
manifest.json     prg32-metadata-1.0 object + assets + architectures + colophon
icon.png          64x64 palettised PNG
splash.png        320x200 attract-mode frame from the QEMU firmware (the Store's screenshot slot)
*.prg32           one file per architecture: esp32c6 and qemu
```

The manifest is generated by `scripts/pack-store-bundle.sh` from `metadata/metadata.json` and
`metadata/colophon.json`. The Store rebuilds every cartridge from it; the rebuilt images are about
54.5 KB, with about 11 KB free in the 64 KiB slot. The 30-second `assets/store/preview.mp4` passes
PRG32's `tools/validate_cartridge_media.py`; it is repository media and not part of the bundle.

## Pack and validate

```bash
scripts/build.sh && scripts/pack-store-bundle.sh
```

Expected, with the Store's ingestion code available:

```text
esp32c6  you-have-got-pizza-deluxe-esp32c6.prg32  ... OK [store-ingest]
qemu     you-have-got-pizza-deluxe-qemu.prg32  ... OK [store-ingest]
you-have-got-pizza-deluxe-1.0.0-store.zip: READY for submission (store-ingest)
```

## Before submitting

- [x] `tests/run_tests.sh`: all suites pass
- [x] `scripts/build.sh`: both cartridges, budgets respected, position independence proven
- [x] `scripts/check_hosts.sh`: PRG32-QT and QEMU pass
- [x] `scripts/pack-store-bundle.sh`: `READY for submission (store-ingest)`
- [ ] Hardware acceptance on an ESP32-C6 ([testing.md](testing.md))
- [ ] Metadata reviewed by the project owner: Store id, authors, license, description
- [ ] Human approval of the release

## Submitting (authenticated, human-controlled)

No script here contacts a Store, and no credentials are stored. A maintainer with a Store account
creates a personal Bearer token (`/auth/tokens`) and submits from the PRG32 checkout:

```bash
python3 -m prg32 store publish-bundle ../YouHaveGotPizza-DeluxeEdition/dist/you-have-got-pizza-deluxe-1.0.0-store.zip --store-url https://store.prg32.uniparthenope.it/ --token "$PRG32_STORE_TOKEN"
```

The Store answers `{"status": "pending", "review_required": true, ...}`. The cartridge appears in the
catalog only after an editor verifies it.

## Releasing a new version

1. Bump `version`, `updated_at` and `release_date` in `metadata/*.json`; add to `CHANGELOG.md`.
2. Re-run the checklist; the bundle takes its name from the version.
3. Run `scripts/make_docs_data.sh`, and update numbers quoted in `docs/`.
